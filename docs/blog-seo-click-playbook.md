# FinMap Blog SEO Click Playbook

## 클릭 수 저조 원인 분류

1. 낮은 노출: sitemap 포함, canonical, hreflang, SSR 본문, 카테고리/홈 내부 링크를 먼저 확인한다.
2. 노출은 있지만 낮은 CTR: title, meta description, h1, 첫 문단이 검색자의 문제와 결과를 바로 말하는지 확인한다.
3. 낮은 평균 순위: 본문 깊이, 예시, 표, FAQ, 관련 글 클러스터, 계산기 연결을 보강한다.
4. 색인됐지만 클릭이 거의 없음: 검색 의도와 글 구조가 어긋난 경우로 보고, 첫 화면에서 얻는 답을 명확히 만든다.

## Title 규칙

- 한국어: 자연어 질문, 문제, 비교, 숫자, 기준, 계산 예시를 우선한다.
- 영어: 직역을 피하고 `calculator`, `simulator`, `monthly investment`, `CAGR`, `DCA`, `retirement` 같은 실제 검색 표현을 자연스럽게 쓴다.
- 너무 넓은 제목보다 "누가 무엇을 판단할 수 있는가"가 보이는 제목을 쓴다.

## Meta Description 규칙

- 110-160자 안팎으로 작성한다.
- 글에서 얻을 수 있는 결과를 구체적으로 말한다.
- 계산기 연결 글은 "계산기로 확인" 또는 "try the calculator"처럼 다음 행동을 넣는다.
- 같은 설명 문장을 여러 글에 반복하지 않는다.

## 권장 글 구조

1. 검색자가 바로 이해할 수 있는 2-3문장 요약
2. 핵심 계산식 또는 핵심 개념 박스
3. 현실적인 예시
4. 표 1-2개
5. 흔한 오해
6. 관련 계산기/도구 링크
7. 관련 글 3-5개
8. FAQ 3-5개
9. Article JSON-LD
10. FAQPage JSON-LD는 실제 FAQ가 본문에 있을 때만 추가

## 내부 링크 원칙

- 홈과 카테고리 페이지는 대표 글과 도구로 연결한다.
- 블로그 상세는 같은 언어의 관련 글 3-5개와 관련 계산기 1-3개를 제공한다.
- 도구 페이지는 사용자가 입력값을 정하는 데 도움이 되는 블로그 글로 연결한다.
- 부동산 대시보드는 대출, 예산, 전월세/매수 판단, 지역 비교 글로 연결한다.
- 한국어 페이지는 한국어 글/도구, 영어 페이지는 영어 글/도구로 연결한다.

## 측정 제안

현재 조회수 카운터는 `slug`와 `lang` 중심이라 검색 유입 품질 분석에는 부족하다. 별도 이벤트 테이블을 둔다면 다음 정도만 저장한다.

- `page_path`
- `canonical_path`
- `lang`
- `slug`
- `category`
- `referrer_origin`
- `utm_source`
- `utm_medium`
- `created_at`
- `user_agent_hash` 또는 세션 단위 익명 해시

IP 원문은 저장하지 않는다. 레거시 URL은 저장 전에 canonical path로 정규화한다.
