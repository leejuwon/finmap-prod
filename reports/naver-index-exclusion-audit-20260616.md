# Naver Index Exclusion Technical Audit

## 후속 점검 메모 - 2026-06-16

- `/en/market/indices` canonical mismatch 최소 패치를 적용했다.
- 변경 범위: `pages/market/indices.js`에서 `router.locale` 기반 `currentLocale`을 계산하고 `SeoHead`에 `locale={currentLocale}`을 전달했다.
- 콘텐츠 번역, SEO title/description, sitemap, RSS, robots 구조는 변경하지 않았다.
- `npm.cmd run build` 성공. postbuild가 `public/sitemap-0.xml`을 재생성했지만 이번 작업 범위가 아니므로 원복했다.
- 빌드 산출물 head 검증:
  - `.next/server/pages/ko/market/indices.html`: canonical `https://www.finmaphub.com/market/indices`
  - `.next/server/pages/en/market/indices.html`: canonical `https://www.finmaphub.com/en/market/indices`

## 한국어 요약

2026-06-16 기준 실제 운영 도메인 `https://www.finmaphub.com`에 대해 `public/sitemap.xml`, `public/sitemap-0.xml`, `/rss.xml`, 수동 URL 35개를 합쳐 고유 URL 213개를 점검했다.

핵심 결론은 다음과 같다.

- `posts`, `tools`, `category`, `market` 주요 페이지에 광범위한 `noindex`가 적용된 증거는 발견하지 못했다.
- sitemap URL 199개 중 `SITEMAP_NOINDEX_MISMATCH`는 0건이다.
- 점검 대상 HTML 페이지에서 `meta robots noindex`는 0건이다.
- `X-Robots-Tag: noindex`는 수동 점검에 넣은 `/api/market/summary` 1건뿐이며, API 경로에 한정된 의도적 설정으로 보인다.
- `robots.txt`는 `User-agent: *`에 `Allow: /`가 있고 `_next/static`, CSS, JS를 차단하지 않는다. Yeti 전용 차단 규칙도 없다.
- 확실한 기술 오류 후보는 `/en/market/indices` 1건이다. sitemap에는 EN URL이 포함되어 있지만 실제 canonical이 KO URL인 `https://www.finmaphub.com/market/indices`로 나온다.

따라서 이번 네이버 색인제외 361건 급증의 1차 원인을 "사이트 전체 noindex 확산"으로 보기는 어렵다. 다만 `/en/market/indices` canonical mismatch는 실제 색인 제외/중복 판정으로 이어질 수 있는 명확한 오류이며, 부동산 대시보드 query URL은 의도적으로 queryless canonical을 쓰고 있어 네이버에서 중복 URL로 집계될 가능성이 있다.

## 중점 점검 결과

## 주요 코드 근거

- `next.config.js:24`: `headers()`는 캐시 헤더만 설정하고 `X-Robots-Tag`를 설정하지 않는다.
- `proxy.js:7-10`: `/api` 경로에만 `X-Robots-Tag: noindex, nofollow`를 설정한다.
- `proxy.js:19-27`: `_next`, 정적 확장자, `xml/txt/css/js` 등은 proxy 정규화 로직에서 제외한다.
- `proxy.js:252`: matcher는 전체 경로지만, 실제 noindex 분기는 `/api` early branch에 한정된다.
- `_components/SeoHead.js:48-80`: canonical/hreflang은 locale 기반으로 만들고, `robots` prop이 있을 때만 meta robots를 출력한다.
- `_components/ToolSeo.js:42,99`: 도구/대시보드 기본 robots는 `index,follow,max-image-preview:large`다.
- `pages/market/real-estate/apt/[aptKey].js:193,205,799`: 아파트 상세만 `noindex,follow` 및 `X-Robots-Tag: noindex, follow`를 설정한다.
- `next-sitemap.config.js:232-270`: RSS/robots/API/apt 상세/query/legacy locale URL을 sitemap에서 제외한다.
- `pages/rss.xml.js:144,174,180`: RSS는 KO 글만 대상으로 하고 draft/noindex 글을 제외하며 `/posts/{category}/{slug}` URL만 만든다.
- `public/robots.txt:2-10`: `User-agent: *`, `Allow: /`, API/admin/private/cdn-cgi만 차단한다.
- `pages/market/indices.js:780-784`: `/market/indices`의 `SeoHead`가 `locale="ko"`로 고정되어 `/en/market/indices` canonical mismatch를 만든다.

### 1. X-Robots-Tag 적용 범위

- `next.config.js`의 `headers()`는 favicon/brand 캐시 헤더만 설정한다. `X-Robots-Tag` 설정은 없다.
- `web.js`에는 전역 `X-Robots-Tag` 설정이 없다.
- `middleware.*` 파일은 없고, Next 16 구조의 `proxy.js`가 있다.
- `proxy.js`는 `pathname.startsWith("/api")`일 때만 `X-Robots-Tag: noindex, nofollow`를 설정한다.
- 같은 파일에서 `_next`, 정적 확장자, `xml`, `txt`, `css`, `js` 등은 early return으로 통과한다.

판정: API에 한정된 의도적 noindex로 보이며, HTML 주요 페이지로 넓게 번진 증거는 없다.

### 2. meta robots noindex

- 공통 `_components/SeoHead.js`는 `robots` prop이 있을 때만 `<meta name="robots">`와 `<meta name="googlebot">`를 출력한다.
- 주요 `posts/tools/category/market` 페이지 HTTP 점검 결과 `NOINDEX`는 0건이다.
- `_components/ToolSeo.js`는 기본값으로 `index,follow,max-image-preview:large`를 넘긴다.
- 아파트 상세 `pages/market/real-estate/apt/[aptKey].js`만 `seoRobots = 'noindex,follow'`와 `X-Robots-Tag: noindex, follow`를 함께 설정한다.

판정: 주요 색인 대상 페이지에 잘못 들어간 meta noindex는 발견하지 못했다.

### 3. canonical 자기 참조

- 대부분의 sitemap/RSS/수동 주요 HTML URL은 self-canonical이다.
- 예외: `/en/market/indices`가 200 응답이지만 canonical을 `https://www.finmaphub.com/market/indices`로 출력한다.
- 원인: `pages/market/indices.js`의 `SeoHead` 호출이 `locale="ko"`로 고정되어 있다.
- 부동산 query URL은 200 응답이고 canonical을 queryless `/market/real-estate` 또는 `/en/market/real-estate`로 둔다. 이는 중복 URL 방지 목적의 의도적 canonical로 보이나, 네이버 색인제외 화면에서는 중복/대체 canonical 성격으로 집계될 수 있다.

판정: 확실한 기술 오류는 `/en/market/indices` canonical mismatch다.

### 4. sitemap.xml / sitemap-0.xml

- `/sitemap.xml`: 200, `application/xml`
- `/sitemap-0.xml`: 200, `application/xml`
- `public/sitemap-0.xml` loc 수: 199
- `SITEMAP_NOINDEX_MISMATCH`: 0건
- HTTP error: 0건

- `/api/`, query parameter URL, `/rss.xml`, `/robots.txt`, `/market/real-estate/apt/*`는 sitemap에서 발견되지 않았다.
- KO/EN post/category/tool/market URL은 대부분 hreflang 쌍으로 들어간다.

판정: sitemap 자체가 noindex URL을 대량 제출하고 있는 문제는 발견하지 못했다.

### 5. rss.xml

- `/rss.xml`: 200, `application/rss+xml; charset=utf-8`
- RSS item URL: 50개
- `pages/rss.xml.js`는 KO 글만 포함하고, `draft`, `noindex`, `robots: noindex` 글을 제외한다.
- RSS item URL은 `/posts/{category}/{slug}` 형태로 query parameter나 API URL을 만들지 않는다.

판정: RSS가 잘못된 URL이나 noindex URL을 대량 공급하는 증거는 없다.

### 6. /ko, /en, /posts/category/lang/slug 구조

- `/ko`는 `/`로 301 redirect된다.
- `/en/en`과 `/en/en/tools`는 각각 `/en`, `/en/tools`로 301 redirect된다.
- `/posts/{category}/ko/{slug}`, `/posts/{category}/en/{slug}` 계열 레거시 URL은 canonical 최종 URL로 redirect된다.
- `SeoHead`는 내부에서 `/en`, `/ko` prefix를 정규화한 뒤 locale에 따라 canonical/hreflang을 생성한다.

판정: 레거시 locale 구조는 대체로 redirect로 정리되어 있다. 다만 `/en/market/indices`는 페이지가 locale을 KO로 고정해 이 규칙을 깨고 있다.

### 7. 부동산 상세/query URL noindex 범위

- 실제 아파트 상세 라우트 `pages/market/real-estate/apt/[aptKey].js`는 `noindex,follow`와 `X-Robots-Tag: noindex, follow`를 함께 설정한다.
- `next-sitemap.config.js`는 `/market/real-estate/apt/*`, `/en/market/real-estate/apt/*`를 sitemap에서 제외한다.
- 템플릿 URL `/market/real-estate/apt/[aptKey]`, `/en/market/real-estate/apt/[aptKey]`는 각각 대시보드로 301 redirect된다.
- 실제 유효 aptKey 샘플은 `NAVER_AUDIT_APT_SAMPLE_KEY`가 없어서 이번 실행에는 포함하지 않았다. 스크립트는 해당 환경 변수를 넣으면 실제 상세 URL과 query URL을 추가 점검한다.

판정: 아파트 상세 noindex는 의도한 범위로 보이며, sitemap에는 포함되지 않는다.

### 8. robots.txt / Yeti / 정적 리소스

- `public/robots.txt`는 `User-agent: *`, `Allow: /`를 둔다.
- 차단은 `/api/`, `/admin/`, `/private/`, `/cdn-cgi/`뿐이다.
- `_next/static`, CSS, JS, 이미지 경로는 차단하지 않는다.
- Yeti 전용 `Disallow`가 없다.

판정: robots.txt 때문에 네이버가 CSS/JS를 못 가져가거나 주요 페이지를 크롤링하지 못하는 문제는 발견하지 못했다.

## 확실한 기술 오류 패치 제안

### P1. `/en/market/indices` canonical mismatch 수정

원인:

- `pages/market/indices.js`에서 `SeoHead`에 `url="/market/indices"`와 `locale="ko"`를 고정 전달한다.
- 그 결과 `/en/market/indices`도 canonical을 KO URL로 출력한다.
- `public/sitemap-0.xml`에는 `/en/market/indices`가 제출되어 있어 sitemap URL과 canonical이 충돌한다.

패치 방향:

- 같은 파일에 이미 `useRouter()`가 있으므로 `router.locale === "en" ? "en" : "ko"`를 계산해 `SeoHead`의 `locale`에 전달한다.
- 콘텐츠까지 EN으로 바꾸는 작업은 별도다. 이번 패치는 canonical/hreflang 기술 오류만 고치는 범위가 적절하다.

예상 효과:

- `/en/market/indices`의 canonical이 `https://www.finmaphub.com/en/market/indices`로 정렬된다.
- 네이버/구글이 sitemap 제출 URL을 자기 canonical로 해석할 수 있다.

## 주의할 관찰 사항

- 부동산 대시보드 query URL은 의도적으로 queryless canonical을 사용한다. 이는 중복 방지 정책으로 자연스럽지만, 네이버에서 query URL을 많이 발견하면 색인제외 사유가 "중복/대체 canonical"로 늘어날 수 있다.
- KO/EN URL이 모두 sitemap에 포함되어 있다. hreflang 구조 자체는 정상이나, 네이버가 한국어 중심으로 평가하는 경우 EN URL의 품질/중복 판단은 별도로 모니터링하는 것이 좋다.
- HTTP 결과 표의 한글 일부가 터미널 표시 환경에 따라 깨져 보일 수 있으나, 이번 감사의 핵심 필드는 status, redirect, canonical, robots, X-Robots, body length다.

## Class Definitions

- `INDEXABLE`: 2xx HTML page with no noindex signal, non-empty body, and self-matching canonical.
- `NOINDEX`: HTML meta robots or googlebot contains noindex.
- `X_ROBOTS_NOINDEX`: HTTP `X-Robots-Tag` contains noindex.
- `REDIRECT`: input URL redirects before the final response.
- `CANONICAL_MISMATCH`: final HTML canonical differs from final URL.
- `SITEMAP_NOINDEX_MISMATCH`: sitemap URL resolves with meta or HTTP noindex.
- `EMPTY_BODY`: HTML body text is below the configured threshold.
- `DUPLICATE_CANONICAL`: multiple checked URLs declare the same canonical URL.
- `HTTP_ERROR`: final status is 0, 4xx, or 5xx.
